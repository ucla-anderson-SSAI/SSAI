App Development Kit

Weeks 8-10: Product Sprint

What This Kit Is For

This kit gives your team a working starting point for a small AI-powered web app. You will not begin from a blank screen. Instead, you will define the app idea, customize the starter files with Cowork/Codex, test the app on your computer, and then deploy it to Railway so other people can open it through a public URL.

The goal is not to become a software engineer in one week. The goal is to understand the basic workflow behind many AI applications: a user enters a request, the app sends that request to a model through an API, the model returns an answer, and the app displays the result.

This kit focuses on apps that use LLM APIs. You may also use a machine learning model, such as XGBoost, or a computer vision model, such as a CNN, if your app idea depends on a specific dataset. The steps are mostly the same, except that instead of the Gemini API you will need the relevant modeling packages, such as sklearn or tensorflow. Reach out to the instructor if you are not sure which approach your app needs.

Phase 1: Initial Setup

Open Terminal on macOS or PowerShell on Windows. In the command-line blocks below, $ and PS> show where the command line starts. Type only the command that comes after those symbols.

1. Create the Project Folder

  1. Download and unzip App_Development_Kit.zip.
  2. Place the unzipped folder on your Desktop.
  3. Rename the folder myapp.
  4. Open the folder in Cowork/Codex.
  5. Ask Cowork/Codex to read AppPlan.md and App_Development_Kit.html before editing anything.

2. Install Node.js and npm

Node.js lets the starter app run on your computer. npm comes with Node.js and installs the app’s dependencies. In plain English, npm reads the app’s setup file and downloads the pieces the app needs to work.

On macOS with Homebrew:

$ brew install node

On Windows with PowerShell:

PS> winget install -e --id OpenJS.NodeJS.LTS

If brew or winget is not available, or if the command-line installation gives you trouble, use the installer at nodejs.org and choose the current LTS version. Then reopen Terminal or PowerShell and check that Node and npm work. 

$ node --version
$ npm --version

If both commands print version numbers, continue.

3. Install the Railway Command-Line Tool

Railway is the service that will host your app online. The command-line tool lets you send the app from your computer to Railway.

Recommended on macOS, Windows, or Linux after Node.js is installed:

$ npm install -g @railway/cli

Alternative on macOS with Homebrew:

$ brew install railway

Check that Railway installed:

$ railway --version

4. Create the External Accounts and Key

  1. Create or sign into a Google account. A personal Google account may be simpler if a school or work account blocks API key creation.
  2. Go directly to the Google AI Studio API Keys page: aistudio.google.com/app/apikey.
  3. Click Create API key. If Google asks you to choose a Cloud project, choose the option to create the key in a new project.
  4. Copy the key when it appears and keep it private. You will paste it into .env in Step 6 and add it to Railway later during deployment.
  5. Create or sign into a Railway account at railway.com.
  6. The Railway free trial should work for the sprint. It includes credits for up to 30 days. If you want the app to keep running after the trial, upgrade to the Hobby plan, which is $5 per month and includes $5 of usage.

5. Install the App’s Dependencies

In Terminal or PowerShell, move into the app kit folder. The exact folder name may differ on your computer.

On macOS:

$ cd ~/Desktop/myapp
$ npm install

On Windows PowerShell:

PS> cd "$env:USERPROFILE\Desktop\myapp"
PS> npm install

This installs the software pieces the starter app needs. It will create a folder called node_modules. Do not edit that folder.

6. Add Your Gemini API Key Locally

The app needs your Gemini API key to call Gemini when it runs on your computer. The downloaded kit already includes a local settings file called .env. Open .env and replace your_key_here with your real key. If you do not see the file in Finder or File Explorer, ask Cowork/Codex to open .env for you. 

GEMINI_API_KEY=your_real_key_here
GEMINI_MODEL=gemini-2.5-flash
PORT=3000

Phase 2: Prototype the App

7. Define the First Version of the App

Open AppPlan.md and fill in the app idea section: use case, intended user, user input, model output, model approach, and whether the app needs source material or a dataset. This is your direct instruction to Cowork/Codex about what to build. The purpose is not to design the perfect app on the first try. The purpose is to get something basic working; once the simple version runs, you can iterate with Cowork/Codex to improve the prompt, interface, examples, and source material.

8. Ask Cowork/Codex to Customize the Starter App

The purpose of this step is to observe what it is like to ask for one concrete change, test it, and revise. You do not need to finish the whole product here. Get one useful change working, then keep building later.

Start with one clear instruction: 

> Read AppPlan.md and App_Development_Kit.html. Customize this starter app for the app idea. Build the simplest working version first. Update the visible text, sample question, system prompt, and response format. Keep the app deployable on Railway.

Then try one specific change. For example: 

> Add a button that allows the user to upload documents for RAG. Use the uploaded document as source material and make the answer clear when the document does not contain enough information.
> Change the colors and fonts to feel clean, professional, and easy to scan. Use dark blue headings, a white background, light gray borders, and a modern sans-serif font.
> Add a saved results panel that keeps a running history of the user's questions and the model's answers during the session, with a clear button to reset the history.

A system prompt is the instruction that tells the model what role to play, who the user is, what rules to follow, and what format to return. Ask Cowork/Codex to make the system prompt explicit and easy for your team to edit later.

9. Run the App on Your Computer

$ npm run dev

Open the local address shown in the terminal, usually http://localhost:3000. Test the starter app with one question.

Important: this command keeps running because it is keeping the local app alive. When you are done testing, return to the terminal and press Ctrl-C.

Phase 3: Deploy on Railway

10. Log Into Railway

$ railway login
$ railway whoami

The login command opens a browser window. After logging in, return to the terminal.

11. Create the Railway Project

Run this from inside the project folder.

$ railway init

If Railway asks questions, choose your workspace or account, create a new project, and use the current folder as the app.

12. Add the Gemini Key to Railway

The .env file works only on your computer. Railway needs its own copy of the key. 

$ railway variable set GEMINI_API_KEY="YOUR_KEY_HERE"
$ railway variable set GEMINI_MODEL="gemini-2.5-flash"

13. Deploy the App

$ railway up

Railway uploads the folder, installs what the app needs, and starts it in the cloud.

14. Create a Public URL

$ railway domain

Railway will give you a free Railway-provided URL. This is the easiest class option and does not require buying or managing a domain. Railway currently documents these as *.up.railway.app URLs. If Railway gives you an option to choose or edit the subdomain, use a short readable name related to your app; otherwise, keep the generated URL.

Phase 4: Iterate the Product

15. Pick One Improvement

Once the first deployed version works, choose one improvement at a time. Good next steps include a clearer app name, a cleaner visual design, a better sample question, a more specific system prompt, a new input field, or a more useful answer format.

16. Ask Cowork/Codex for the Change

Be specific about what should change and what should stay the same. For a design pass, use: 

> Improve the visual design of this app for the intended user in AppPlan.md. Use App_Development_Kit.html as the guide. Keep the same functionality and Railway deployment path. Make the interface clearer, more polished, and easier to scan.

For a functionality change, use: 

> Add one useful feature to this app based on AppPlan.md. Use App_Development_Kit.html as the guide. Keep the app simple. Explain which files you changed, then tell me how to test it locally before redeploying.

17. Test and Redeploy

After each change, run the app locally, test one or two realistic prompts, and then deploy again. 

$ npm run dev
$ railway up

Appendix: Common Fixes

Problem Likely Fix
node or npm is not found Install Node.js, then reopen Terminal or PowerShell. On Windows, try the Node installer if winget is not available.
brew is not found on macOS Use the Node.js installer from nodejs.org. After Node is installed, use npm install -g @railway/cli for Railway.
winget is not found on Windows Use the Node.js installer from nodejs.org, then reopen PowerShell and check node --version and npm --version.
railway is not found Install the Railway command-line tool, then reopen Terminal or PowerShell. If the npm install fails, make sure Node.js and npm are installed first.
npm install fails Make sure you are inside the myapp folder. Ask Cowork/Codex to inspect package.json and explain the error.
PowerShell blocks a command Try opening PowerShell as a normal user, not administrator. If script execution is the issue, ask Cowork/Codex to translate the command for Windows.
npm run dev never returns to the prompt This is normal. The local app is running. Press Ctrl-C to stop it.
The app says the API key is missing Add GEMINI_API_KEY to .env locally and to Railway variables for deployment.
The Railway app crashes Ask Cowork/Codex to check that the app reads Railway’s assigned port.
The model gives generic answers Make the user, task, and desired output more specific in AppPlan.md and the app prompt.
The app should use RAG but answers from general knowledge Put the right source text in docs/knowledge_base.md and ask Cowork/Codex to make the model rely on retrieved source material.
RAG gives weak answers Replace docs/knowledge_base.md with better source text and ask source-specific questions.
railway login does not complete Check the browser login window. If it opened in the wrong browser, copy the login URL into the browser where you are signed into Railway.
The deployed app says the API key is missing Set the key in Railway with railway variable set GEMINI_API_KEY="YOUR_KEY_HERE", then deploy again.
The Railway URL looks random Use it anyway for class, or check the Railway service settings to see whether Railway offers an option to edit or regenerate the Railway-provided subdomain.

File or Folder What It Is For
public/index.html The visible page structure: title, labels, and form fields.
public/app.js The browser-side behavior: collects form inputs and displays the model answer.
public/styles.css The visual styling for the page.
server.js The app logic that receives the user request, calls Gemini, and returns the answer.
docs/knowledge_base.md Optional source text for RAG. Replace this if your app needs to answer from documents.
